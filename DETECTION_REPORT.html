Executive Summary

This plagiarism detector employs a multi-layered approach combining:

Detection Methods

1. Abstract Syntax Tree (AST) Analysis

The AST analyzer parses source code into a tree representation, capturing program structure independently of variable names and formatting.

Algorithm Overview

Purpose: Detect structural plagiarism by comparing code organization and control flow.

Method: Longest Common Subsequence (LCS) matching on AST nodes with penalties for size mismatches.

Processing Steps:
  1. Tokenization: Break source code into meaningful tokens (keywords, operators, identifiers)
  2. AST Building: Construct abstract syntax tree from token stream, identifying:
    • Functions and declarations
    • Control structures (if, switch, loops)
    • Assignments and expressions
    • Return statements
  3. Node Sequencing: Flatten AST into sequence of node types and labels
  4. LCS Matching: Find longest common subsequence of nodes between two files
  5. Similarity Scoring: Apply penalties for structural differences
Node Types Detected:
Node Type Description Example
PROGRAM Root program structure Entire file
FUNCTION Function declaration void myFunc()
IF_CONDITION If statement if (x > 5)
LOOP_FOR For loop for (int i=0; i
LOOP_WHILE While loop while (condition)
RETURN Return statement return result;
ASSIGNMENT Assignment operation x = 10;
EXPRESSION Generic expression a + b * c
Scoring Formula:
finalScore = (matched_nodes / max_size) × size_penalty × conservative_scale Where: - matched_nodes = Length of longest common subsequence - max_size = Maximum AST node count between files - size_penalty = 1.0 (perfect) when size ratio ≥ 80% = 0.75-1.0 (scaled) when structures differ - conservative_scale = 0.85 (to reduce false positives) - Special case: Perfect matches (99%+ similarity) return 100%
Advantages:
  • Detects structural plagiarism even with variable name changes
  • Immune to formatting and whitespace differences
  • Identifies control flow restructuring (if→switch substitution)
  • Works across different programming languages with same logic
Limitations:
  • Requires compilable/parseable code
  • May miss plagiarism in functionally equivalent but structurally different code

2. N-Gram Analysis (Unigram, Bigram, Trigram)

N-gram analysis breaks text into overlapping sequences of n words, capturing semantic and syntactic patterns.

Algorithm Overview

Purpose: Detect textual similarity through word sequence and phrase matching.

Processing Steps:
  1. Text Cleaning: Remove non-alphanumeric characters, convert to lowercase
  2. Tokenization: Split text into word tokens
  3. Stop Word Removal: Filter common words (the, and, is, etc.)
  4. N-gram Generation:
    • Unigram (n=1): Individual words
    • Bigram (n=2): Two-word phrases
    • Trigram (n=3): Three-word sequences
  5. Frequency Counting: Track occurrence of each n-gram
  6. Similarity Calculation: Cosine similarity on frequency vectors
Example:
Text: "The quick brown fox jumps over the lazy dog" Unigrams: [quick, brown, fox, jumps, lazy, dog] Bigrams: [quick brown, brown fox, fox jumps, jumps over, lazy dog] Trigrams: [quick brown fox, brown fox jumps, fox jumps over, jumps over lazy]
Scoring Formula (Cosine Similarity):
similarity = (A · B) / (||A|| × ||B||) Where: - A · B = Dot product of frequency vectors - ||A||, ||B|| = Magnitude (L2 norm) of vectors - Result: 0 (no match) to 1.0 (identical)
Advantages:
  • Captures semantic similarity through phrase patterns
  • Works with unstructured text and comments
  • Resistant to paraphrasing up to a point
  • Fast computation even for large documents

3. Cosine Similarity & TF-IDF Scoring

Algorithm Overview

Method: Vector space model treating documents as high-dimensional vectors.

Purpose: Quantify how similar two text documents are numerically.

Calculation Method:
For each document, compute frequency vector: vector = [freq_word1, freq_word2, ..., freq_wordN] Cosine similarity = dot_product(v1, v2) / (norm(v1) × norm(v2))
Interpretation:
  • 1.0: Perfect semantic match
  • 0.7-0.99: Very similar (likely plagiarism)
  • 0.4-0.7: Moderately similar
  • 0.0-0.4: Low similarity (different documents)

Scoring & Thresholds

Overall Similarity Score Calculation

The final plagiarism risk is determined by combining multiple algorithms:

final_score = WEIGHTED_AVERAGE( ast_similarity × 0.30, // 30% weight - structural match unigram_similarity × 0.20, // 20% weight - individual words bigram_similarity × 0.25, // 25% weight - two-word phrases trigram_similarity × 0.25 // 25% weight - three-word sequences )

Batch Analysis Mode

For analyzing multiple files simultaneously to identify clusters of similar documents.

Batch Processing Algorithm

Purpose: Efficiently compare N files against each other and identify plagiarism clusters.

Process:
  1. Fingerprinting: Create lightweight signature for each file (unigram frequencies)
  2. Candidate Filtering: Quickly identify file pairs exceeding 30% fingerprint similarity
  3. Full Analysis: Run complete multilayer analysis on candidate pairs
  4. Cluster Detection: Group files with suspicious similarities into clusters
  5. Graph Analysis: Build connected components to identify probable original vs copies
Output Data Structures:
PlagiarismCluster { members: [FileNode, ...] // Files in cluster internalPairs: [FilePair, ...] // Suspicious file pairs } FilePair { fileIdx1: int fileIdx2: int similarity: double // Overall similarity score } FileNode { filename: string isProbableOriginal: bool // Heuristic based on degree suspiciousPairCount: int }
Advantages:
  • Fast preliminary filtering with fingerprinting
  • Detects copy chains (A copied from B, B from C)
  • Identifies probable original documents
  • Scales to handle hundreds of files
